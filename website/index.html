Watch one question get answered.

One recorded answer, step by step. Claude Code writes the SQL. The database does the counting.

  1. A buyer asks

    Your application says who is asking. The model cannot change it.

    How many invoices for my orders are overdue?

  2. Claude Code reads the whole question

    No classifier and no router. The buyer's data guide comes with the question, and it defines the word overdue.

    reference_erp/knowledge/guide/buyer.md

    overdue_invoices (supplier_invoices): An invoice is overdue when its status is approved and its due_date is before today. Use the date given with the question as today, not the database clock.

  3. It picks a tool and writes one query

    The tool is run_query. The SQL is its only argument: no tool takes a user name.

    run_query, as recorded

    SELECT COUNT(*) AS overdue_count,
       SUM(i.total_amount) AS overdue_total
FROM supplier_invoices i
JOIN purchase_orders o ON o.id = i.purchase_order_id
WHERE o.deleted_at IS NULL
  AND i.status = 'approved'
  AND i.due_date < DATE '2026-06-30'

  4. The database applies the buyer's rule

    The query counts every row this buyer may read. Other buyers' rows never leave the database.

    reference_erp/policy.toml

    [tables.supplier_invoices]
rows.buyer = "purchase_order_id IN (SELECT id FROM purchase_orders WHERE buyer_id = {user_id})"

  5. The answer goes back

    First a second query checks that the join dropped no invoice. The audit record keeps both. Recorded: 3 turns, 9.1 seconds, $0.03, graded correct.

    17 invoices for your orders are overdue. Together they come to 3,482,105.52 USD.

The question, the SQL and the answer are quoted from the result file of the run recorded 2026-11-11 with claude-opus-5-5.

Run it on your machine.

You need Docker, or Python 3.11 or later with PostgreSQL.

The sample is a made-up purchase-to-pay company with three roles. Sign in with any seeded user and the password workcell-demo.

Answers call a model and cost money. The server needs ANTHROPIC_API_KEY.

Start the database, load the data, install the guard
git clone https://github.com/Shivam7414/agent-workcell.git
cd agent-workcell
cp .env.example .env
docker compose up -d db               # PostgreSQL on 127.0.0.1:54329
docker compose run --rm seed          # the sample: 3,000 purchase orders
docker compose run --rm guard apply   # install and check the data guard
Start the answer server and the chat page
pip install -e ".[claude]"
python -m agent_workcell.server       # http://127.0.0.1:8080
python -m reference_erp.host_app      # http://127.0.0.1:8081
